# Li4Wei · 理四维

面向 PICO OS 6 / Project Swan 的原生四维探索游戏，采用 **OpenXR + OpenGL ES 双眼 VR**，Kotlin 几何/玩法核心与 C++ 渲染后端。当前共有 **3 章、15 关、9 课立体讲解**。

## 安装正式版

[下载理四维 v0.1.0 APK](https://github.com/zMr2010/Li4Wei/releases/download/v0.1.0/Li4Wei-v0.1.0.apk)。同一安装包面向 PICO 和 Meta Quest 的 ARM64 Android OpenXR 设备，最低 Android 12L（API 32）。在已开启开发者模式并允许 USB 调试的设备上运行：

```sh
adb install -r Li4Wei-v0.1.0.apk
```

在头显应用库中打开「理四维」。正式版使用独立包名 `com.fourthward.li4wei`，可与开发版并存，两者分别保存关卡进度。

## 关卡路线

九个教程构成唯一主线，按此顺序完成：

```text
1-1 → 1-2 → 1-3 → 2-1 → 2-2 → 2-3 → 3-1 → 3-2 → 3-3
                │                                  │
                ├─ 1-4 交错门廊                    ├─ 3-4 追光
                ├─ 1-5 隐藏回廊                    ├─ 3-5 漂游之间
                └─ 1-6 信标归航                    └─ 3-6 错峰门廊
```

完成 1-3 后，2-1 与三个移动挑战同时开放；完成 2-3 后开放 3-1；完成 3-3 后开放三个运动挑战。挑战均可选、同组可任意顺序游玩，完成与否不影响后续教程。教程完成后的 N 沿主线进入下一课；挑战完成或主线结束后，N 返回关卡路线。

启动后会听到一次「Li4Wei」呼号。展厅左侧的关卡路线可选关或续玩，右侧悬浮的超立方体展示四维旋转。新玩家可以开始第一课，有存档的玩家可以继续上次的关卡。游戏中也可以从掌心面板打开「关卡路线」。教程在左侧纵向贯穿，可选挑战从对应课程向右并排展开。地图每次最多展示六层、九个节点；上下浏览、章节编号和快捷槽位保持一致。连接关系与实际解锁来自同一份依赖数据：绘图约简冗余线，解锁仍检查完整教程前缀。存档使用稳定关卡 ID，旧完成记录保留可重玩；未完成的新课不能通过旧存档缺口跳过前置教程。

## 四维几何与移动

世界坐标为 `(X,Y,Z,W)`。唯一的角度 θ 决定切片水平方向，Z 为重力方向、W 保持不变：

```text
Bθ(s,z,w) = (s cosθ, s sinθ, z, w)
world(q) = origin + Bθq
旋转时：origin' = world(q玩家) − Bθ' q玩家
```

画面是四维物体与当前三维超平面的**真实相交**。盒体用八个半空间求凸截面；超球截面半径为 `sqrt(R²−d²)`。不与切片相交的物体不可见，不显示完整四维投影或离面幽灵标记。旗帜、路标 glyph 仅标注已存在的真实截面；地面网格对应固定四维 Z=0 的行走下界。

原生入口 `vr/OpenXrActivity` 使用运行时预测双眼视图与真实 6DoF，OPAQUE 合成覆盖整个视野，不启动默认房间。系统安全边界仍由运行时管理。头部转动改变视角，不改变 θ。WASD 与左摇杆按当前头显的水平朝向移动，抬头、低头及侧倾不会引入升降或改变水平速度。Space 上升、左右 Shift 均可下降，升降沿固定重力轴；与水平移动同时按下时合并限速。现实走动、键盘/手柄移动都经过胶囊体连续碰撞；撞墙时抵消本帧被拒绝的位移，不累积退回距离，稍微后退就能离开墙。人工位移通过切片原点实现，保留原始双眼、头手相对位置和自然眼高。

真实头显的上下位移也进行连续头部与身体碰撞检查，正常蹲下、起身保留；持续压向天花板或地面不会拖动脚底，反向移动立即生效。Z=0 可见地面阻止脚底与头部穿入地下，空中 Shift 可下降到地面；实体楼板和屋顶同样阻挡键盘与真实头显位移。模拟器初始头高若已在屋顶外或地面下，仅在可安全修正时调整有效眼高，保留原始追踪位姿及关卡起点。

**辨认章 2-1–2-3 的实际观察固定虚拟位置**，保留转头与 θ，WASD 和升降均不改变位置。三维讲解阶段可通过真实 6DoF 走动观察，键盘移动暂停。**运动章 3-1–3-3 的实际观察允许现实走动、WASD 和升降**。实际阶段以初始切片方向比较运动；转动到其他方向仍可探索，但不能用恒定不变的截面或离开物体后的计时替代对应观察。完成后也可继续走动观察，再按 N 前进。

## 运动与关卡规则

运动对象在四维空间中平移，大小和方向保持不变；屏幕中截面的大小、位置、棱数变化均来自真实相交。球体及两种盒体以 12 秒周期往返。正穿球只有隐藏方向位移；斜穿球增加水平位移；倾斜盒体依次呈现三棱柱、六棱柱、三棱柱，细长盒体同时展示另一种稳定形状的移动截面。

实际观察会检查入口、中央和出口阶段的真实截面特征，并要求短暂连续观察；只等待时间、把球转成始终位于切片内、或走到看不见它的位置，都不会自动完成这三个观察阶段。观察完成后保存进度，N 进入下一关。

移动挑战的建筑在 X/Y/Z/W 八个方向有重叠边界，不能从关卡外绕行。路标必须由玩家实际到达并与切片相交，完成条件不是指定角度口令。H 或掌心「提示」分三级给出观察线索、方向线索和具体走法；默认只显示当前任务。

T 或「返回路标」回到最近实际到达的脚部位置与 θ，运动挑战还恢复当时的运动时间。每次进入关卡都会恢复该关初始位置和 θ。选择关卡或开始探索时立即保存当前关卡，重开会显示「理四维」路线，点「继续」或按 Enter 回到保存关卡的讲解或探索起点。直接点路线卡片会从该关的讲解开始，有些挑战会直接进入探索。已完成关卡的记录也保存到本机。

「追光」的光球在金色停靠点等玩家，随后穿过青色门廊飞向出口。「漂游之间」穿过通道后直达出口。「漂游之间」和「错峰门廊」的障碍均以 8 秒为周期。接触漂游体或移动门会回到关卡起点，恢复初始 θ 和障碍相位。章节地图打开、失焦或追踪不可用时暂停运动与讲解。

## 并列立体讲解与旁白

## 场景材质与设施

建筑与教学展台采用石墨灰、象牙白和少量暖黄的工业配色。实体墙的装甲分区、底带与细缝根据当前真实凸截面生成；颜色门廊保留辨路用途。终点使用带削角底座、支架和双面旗牌的立体标识，路标使用同一套设施语言。标识只随可见的目标截面出现。

世界与教学球体共用 24×48 球面网格和逐顶点柔光材质，保持解析半径；不会给观察对象添加膨胀外壳。教学台增加分层金属边、短校准线和稀疏警示刻线。所有改动由原生网格生成，仍使用原有颜色顶点格式，不改变四维几何、碰撞或通关条件。

本次场景美化在教程主线版本 `32816e3` 完成后开始，单独提交，可独立撤销。

## 空间 HUD 动效

以 [UX is Fine 的 HUD 示例](https://www.uxisfine.com/motion-services)为主要参考，并借鉴 [ak-ui 按钮](https://github.com/YunYouJun/ak-ui/blob/master/src/scss/_ak-button.scss)的快速反馈与窄光带：

- 掌心面板沿深度展开与收起，换页先淡出旧内容，再依次展开卡片；章节连线分段延伸，信号微光沿分支移动。
- 按钮具有固定底座和真实侧面，悬浮抬升 4mm，按下凹入 0.7mm、轻微收缩；悬浮与点击会扫过一束窄光，焦点角标平滑移动。
- 角度条在原生帧率下连续更新；字幕换步淡入，完成状态用细线与角框短暂确认。
- 可见目标与路标使用低幅悬浮标记、基座流光及局部到达反馈；离开真实截面立即清空，不显示隐藏物体。

面板和字幕在场景之后绘制，墙壁与其他物体无法遮挡控件。面板、按钮与标记动效使用每帧 GPU 几何与透明度，文字图集按内容变化更新。按钮接触面保持不变，展开未完成时暂停手指点按，键盘快捷键可随时切页。失焦暂停动效。设计依据与参考时间点见 [docs/MOTION-DESIGN.md](docs/MOTION-DESIGN.md)。

首页和关内共用一张路线图。浅色使用骨白底板和石墨字，深色使用炭灰底板和浅色字。节点用对勾、菱形和锁区分已通过、可进入和未解锁的关卡。黄色标记继续按钮和当前操作，悬停、按压时按钮会实际抬升或下沉。

Git 已保存制作动效前的完整基线 `7a5fd47`，后续动效作为独立功能提交。可通过 `git log --oneline` 查看并用 `git revert <提交号>` 撤销对应改动，不需要删除存档。

## 操作

- 向前伸手并抓握，保持抓握向身体收回，收回越多则前进越远。转头可改变前进方向，辨认章的固定观察仍适用。
- 前伸右手并张开，掌心朝前、手背朝自己。向左横移对应 Q，向右横移对应 E。
- 任一只手张开，掌心朝向自己或朝上，连续保持 3 秒打开面板。面板固定在打开时的掌心附近，收手后仍可操作。关闭时把任一只手伸到面板处，握拳即可。
- 对准按钮，拇指与食指捏合后松开即可点击，也可以直接用食指戳按，或指向同一按钮满 2 秒，等待光标下方的进度条走满。保持指向只会触发一次，移开再指回即可重新计时。在关卡路线上，保持捏合并上下拖动可以浏览其他关卡，松开结束拖动。
- 游戏面板提供 θ 归零、参考平面（挑战关为提示）、重试/返回路标/下一课、关卡路线和外观切换。在首页、关卡路线或掌心面板点「切换深色」或「切换浅色」即可更改外观。首次启动使用浅色，再次启动会记住选择。

| 按键 | 动作 |
| --- | --- |
| F2 | 切换深色／浅色外观 |
| WASD | 按头显当前朝向水平前后／左右移动；辨认章实际观察保持原点 |
| Space / 左右 Shift | 上升 / 下降；受碰撞、固定观察与页面状态限制 |
| Q / E | 唯一的切片角度 θ |
| M | 调试面板 |
| L | 打开 / 收起关卡路线 |
| 1–9（路线中） | 选择当前视窗节点标注的快捷槽；仅已解锁节点可进入 |
| Esc | 返回游戏 |
| ↓ / ↑ 或 PageDown / PageUp 或 [ / ] | 查看前序 / 后续关卡 |
| Tab / Shift+Tab / Enter | 选择前后按钮 / 执行 |
| R 或 P | θ 归零；讲解时重播当前步骤 |
| H | 教程回看讲解；挑战按需增加一级提示 |
| V | 参考平面；挑战显示提示 |
| T | 重试 / 返回路标；讲解从头开始 |
| N | 讲解下一步；教程完成后下一课；挑战完成或主线结束后返回地图 |
| B | 讲解上一步 |

模拟器需点亮左侧「键盘＋笔」输入按钮，确保按键传入游戏。数字键现在按当前页面解释，不再使用旧的全局 7–9 选关方式。真实手势与键盘提供对应操作入口。

## 构建与运行

JDK 21、Android SDK 35 / Build Tools 35.0.0、NDK 28.2.13676358、CMake 3.22.1。两个 APK 都使用 OpenXR Loader 1.1.65，要求 ARM64、OpenGL ES 3 和支持 OPAQUE 双眼显示的 OpenXR 运行时。PICO 版最低 Android API 35，面向 PICO OS 6 / Swan。

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
pico-cli app install app/build/outputs/apk/debug/app-debug.apk --replace
pico-cli app launch com.fourthward.game
```

`local.properties` 保存本机 SDK 路径并排除提交。语音生成需本地 `FISH_API_KEY` 与 macOS `afconvert`；无需在运行游戏时联网。

### Meta Quest 真机测试包

`quest` 模块共享原生 OpenXR 游戏代码与素材，最低 Android API 32，目标 API 34。清单将 Quest 2、Quest Pro、Quest 3 和 Quest 3S 列为测试目标。手柄使用现有的 Oculus Touch 绑定，手部追踪需在头显系统中启用。 [Meta Quest 清单规范](https://developers.meta.com/vr/resources/publish-mobile-manifest/) · [手部追踪配置](https://developers.meta.com/vr/documentation/native/android/mobile-hand-tracking/)

为头显开启开发者模式并授权 USB 调试。在 `adb devices` 的输出中找到 Quest 的序列号，替换下方命令中的 `SERIAL`。安装后也可以从头显的应用库「未知来源」启动。 [Meta 侧载指南](https://developers.meta.com/vr/essentials/quick-start/)

```sh
./gradlew :quest:testDebugUnitTest :quest:assembleDebug
adb devices
adb -s SERIAL install -r quest/build/outputs/apk/debug/quest-debug.apk
adb -s SERIAL shell am start -W -a android.intent.action.MAIN \
  -c com.oculus.intent.category.VR \
  -n com.fourthward.game.quest/com.fourthward.game.vr.OpenXrActivity
adb -s SERIAL logcat -s FourthwardXR AndroidRuntime
```

Quest 真机验收待完成。头显里确认双眼画面、转头和走动、双摇杆移动与转动切片、X 键打开菜单、右扳机推进讲解，以及切换手部追踪后掌心菜单和另一只手的点按。日志中可查看运行时名称、会话状态、左右眼交换链与 GL 错误。

传统 SteamVR PC 头显需要桌面版。Steam Frame 可通过 Lepton 侧载 Android ARM64 应用，Valve 文档中的 Lepton API 30 低于 Quest 包要求的 API 32，需要单独构建并实测。 [Steam Frame 兼容性](https://partner.steamgames.com/doc/steamhardware/steamframe/compatibility) · [Lepton SDK 说明](https://partner.steamgames.com/doc/steamhardware/steamframe/engines/unreal)
